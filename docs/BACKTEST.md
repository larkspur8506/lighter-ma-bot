# 回测（T11）—— Lighter 全历史

本文件记录 `scripts/backtest.py` 的**实跑结果**、**成交假设**、以及与旧系统 HL 基线的
**分层对比**（信号层可比 / 绩效层不可比）。所有数字都可以用第 8 节的命令原样复现；
没有一个数字是手填的。

引擎口径的两条硬约束（代码层面，不是约定）：

| 约束 | 实现 | 测试 |
|---|---|---|
| 信号只能用冻结策略 | `from app.strategy import scan, compute_indicators, exit_triggered` —— 回测**不重写**任何判定 | `tests/test_backtest.py::SingleSourceOfTruthTest`（行为断言 `signals_for` → `scan`） |
| 回撤必须与熔断/面板同一函数 | `app.dd.bootstrap` / `app.dd.advance` 推 TWR 链，`app.dd.evaluate` 取回撤与档位 | `DrawdownUsesAppDdTest`（与 `app.dd` 逐位 `assertAlmostEqual`） |

旧系统踩过的坑是「三个回撤口径混用」（一步算 / 重放算 / 面板算各一套）。这里
**只有一条链**：权益点 → `dd.advance` → `dd.evaluate`，和 `app/watchdog.py`、
`app/views.py` 用的是同一个函数。

## 1. 成交假设清单

| # | 假设 | 说明 / 为什么 |
|---|---|---|
| 1 | **信号**：`app.strategy.scan(bars, symbol, sides=(1,-1))` | 冻结口径（sha256 `8682667…`），多空双向。回测不允许自带第二套判定 |
| 2 | **进场**：信号 bar 的**下一根开盘价** | 与 `Signal.entry_price` 同值；收盘破线 → 下一根开盘才能成交，不能用当根收盘价（那是未来函数） |
| 3 | **止损**：`Signal.stop_price`；多单 `low ≤ stop`、空单 `high ≥ stop` | 4h bar 内用 high/low 判触及，成交价 = 止损价 |
| 4 | **跳空**：开盘已在止损之外 → 按**开盘价**成交 | `long: min(stop, open)` / `short: max(stop, open)`。跳空是真实亏损，不能用止损价粉饰 |
| 5 | **离场**：`app.strategy.exit_triggered`（收盘 vs SMA20） | 与实盘同一函数；成交价 = 当根收盘价 |
| 6 | **入场当根不判离场** | 与 `app.lifecycle.decide_exit` 的 `is_entry_bar` 守卫一致；否则会出现「开盘进、收盘出」的 1 根 bar 交易，实盘不会那么做 |
| 7 | **同 bar 冲突**：止损**优先**于信号离场 | 4h 内无法知道先后；止损是更差的结果，取更差的那个。若反过来，回测会系统性高估收益且永远看不出来（`StopWinsOnSameBarTest` 两个方向各测一次） |
| 8 | **手续费**：0（Lighter taker） | `--fee-bps` 可覆盖。HL 是 0.045%/边，**不能**把 HL 的费率结果搬过来 |
| 9 | **资金费**：Lighter `/api/v1/fundings` 的真实逐小时历史 | 逐 4h bar 按「bar 收盘名义」计提；`direction` 决定哪一边付 |
| 10 | **滑点**：0（`--slippage-bps`） | 一律朝不利方向（多头进贵出便宜）。第 5 节给了 5bps 的敏感性 |
| 11 | **定仓**：`notional = 权益 × risk_pct / 止损距离` | 与 `app/sizing` 同一公式；**不做**交易所精度取整（那是实盘职责，回测要连续口径） |
| 12 | **复利**：每笔按**入场时的盯市权益**定仓 | 与实盘看到账户权益同一口径 |
| 13 | **每标的同时至多一仓** | 与 `app.lifecycle.REJECT_SYMBOL_BUSY` 一致；持仓期间的信号被跳过并计数 |
| 14 | **强平不建模** | 止损上限 10% 配 5x 逐仓：强平线 −19.5% 永远晚于止损（`app/strategy.py` 的 `STOP_MAX` 注释即此假设） |
| 15 | **资金费单位**：API 的 `rate` 是「每小时百分比」→ 小数要 `/100` | 交叉验证：同期 `/funding-rates` 给 Lighter BTC `9.5999e-05`（8h 口径小数 = 0.0096%/8h = 0.0012%/h），与 `/fundings` 的 `rate=0.0012` 自洽 |

### 1.1 资金费的单位与符号（容易错 100 倍的地方）

```
GET /api/v1/fundings?market_id=1&resolution=1h&start_timestamp=…&end_timestamp=…
→ {"timestamp": 1738587600, "rate": "0.0019", "direction": "short", "value": "1.80067750"}
```

* `rate` 是**每小时百分比**：`0.0012` = 0.0012%/h = `1.2e-5` 小数。回测里 `rate/100`。
* `direction="long"` ⇒ **多头付钱**（空头收钱）；`"short"` 反之。
  实测 15,534 个小时点里 BTC `long` 占 13,161（85%）—— 这段行情以多头付资金费为主，
  所以**空头反而是收钱的**（BTC 单独跑时资金费合计 −2.2 USDC，即净收入）。
* 全历史均值：BTC 0.0012%/h、ETH 0.0013%/h、SOL 0.0015%/h（折合约 10–13%/年的多头持有成本）。

> 若把 `rate` 当成小数（少除 100），资金费会放大 100 倍：BTC+ETH+SOL 在 1.33% 档
> 的终值会从 1.50x 掉到 ≈ 0.55x。这是这段代码里最危险的一处，`FundingTest` 用
> `rate="1.0"` → 4 小时 = 4% 把单位钉死。

合计场景的 R 分布（1.33%、含资金费）：

```
止损 36 / 信号离场 171 / 数据末尾 1        多 113 空 95      平均持仓 11.0 根
最好 +17.47R / 最差 −1.01R / 中位 −0.30R   获利笔均 +1.78R，亏损笔均 −0.59R
权益 10,000 → 14,995（×1.500，TWR 指数 1.4995）毛 PnL +5,191.3 / 净 PnL +4,995.3

三个可以自查的一致性点：
1. **最差单笔 = −1.01R**：止损离场就该是 −1R（−1.01 是资金费）；如果出现 −2R，说明止损没生效。
2. 均R = 33.7%×(+1.78) + 66.3%×(−0.59) ≈ **+0.21R**，与表中实际值一致。
3. TWR 指数 1.4995 = 终值/起值（回测没有入金，两者必须相等）。

## 5. 成本敏感性（1.33% 档，合计场景）

| 情景 | CAGR | 终值 | 最大回撤 |
|---|---|---|---|
| 只扣真实资金费（默认） | +25.65% | 1.50x | 22.16% |
| + 手续费 4.5bps/边（= HL 费率，Lighter 实际为 0） | +19.79% | 1.38x | 25.77% |
| + 滑点 5bps/边 | +18.47% | 1.35x | 25.88% |
| 资金费 ×2（压力） | +24.47% | 1.47x | 22.33% |
| 三个一起上（最坏情景） | +12.00% | 1.22x | 29.93% |

为什么费率影响这么大 —— 用换手率解释而不是"感觉"：

```
208 笔，Σ名义 = 973,347 → 换手 97.3× 权益 / 1.77 年 = 54.8×/年（单边），双边 109.7×/年
4.5bps/边 × 109.7 = 4.94%/年 简单成本；CAGR 差 7.0 个点（复利会把简单成本放大）
平均止损距离 3.51%，平均名义/权益 0.455 → 单笔成本 ≈ 0.455 × 0.09% = 0.04% 权益
```

**Lighter 手续费为 0，这是它相对 HL 最大的结构性优势**：同一套信号、同等换手，
HL 每年要交约 5% 的简单成本，Lighter 这行是 0。反过来，Lighter 盘口只有 HL 的
1/5 深，5bps 滑点在薄盘口上是**乐观**估计（小额账户尚可，规模上去会显著变差）。

## 6. 与旧系统（HL）基线的分层对比

旧系统基线（`crypto-ma-alert`，HL 现役，pandas 引擎，6.1 年 / 700 笔）：

| 项 | 旧系统（HL） | 本次（Lighter） | 可比性 |
|---|---|---|---|
| 历史长度 | 6.10 年 | **1.77 年** | ❌ 不可比（29%） |
| 交易笔数 | 700（115/年） | 208（**117/年**） | ✅ 频率同量级 |
| 每笔风险 | 1.33% / 2% / 3% | 同 | ✅ 同口径 |
| 手续费 | 0.045%/边 | **0** | ❌ 不可比 |
| 资金费 | HL 实际 | Lighter 实际（10–13%/年 多头成本） | ⚠️ 各算各的 |
| 盘口深度 | 深 | 约 1/5 | ❌ 不可比 |
| 均R | +0.2442 | **+0.22（毛）/ +0.21（净）** | ⚠️ 同量级，不同样本 |
| CAGR（1.33%） | +39.9% | **+25.65%** | ❌ 不可比 |
| CAGR（2%） | +61.6% | **+33.80%** | ❌ 不可比 |
| CAGR（3%） | +95.0% | **+40.73%** | ❌ 不可比 |
| 最大回撤（1.33%） | 23.3% | **22.16%** | ⚠️ 数值接近，样本不同 |
| 扣资金费 CAGR（1.33%） | +37.2% | **+25.65%**（已含资金费） | ❌ 不可比 |

### 6.1 信号层：**可比**（同一份字节的策略）

* 策略口径是**同一个文件**（`app/strategy.py`，sha256 冻结，T2 逐字节复制），
  所以「什么样的行情会产生信号」这件事两边完全一致 —— 这是唯一可以跨场所比较的层。
* 信号密度：Lighter 3,889 根 bar 产 **1,251 笔信号**（0.322 笔/bar）；
  旧研究 6.1 年 700 笔**成交**、115 笔/年。本次成交 **117 笔/年** —— 折算成年频率
  相差 2%，说明「换市场不换策略」的**信号密度与成交频率处于同一量级**。
* 信号到成交的转化率 16.6%（208/1,251），差额全部是「已有持仓」跳过；
  旧系统的 700 笔也是同样规则（每标的至多一仓）下的产物，所以这一层的对比是成立的。
* 交叉验证：Lighter 1,251 笔信号由两个**独立实现**（`app.strategy` 与
  `scripts/backtest_engine`）逐笔产出，键（bar 时间 + 方向 + 止损价）完全一致
  （第 7 节）。

### 6.2 绩效层：**不可比**（四个结构性差异）

1. **历史长度 1.77 年 vs 6.10 年（29%）**。旧研究的 700 笔覆盖了多轮牛熊；本次只覆盖
   2025-01 → 2026-10 这一段（以多头付资金费为主，BTC 85% 的小时是多头付钱）。同一策略
   在不同市场结构里的 R 分布本来就不同，**年化数字不能互相借**。
2. **手续费 0 vs 0.045%/边**。同一套信号、同等换手，HL 每年付约 5% 的简单成本；
   Lighter 这行是 0。所以 Lighter 的净结果**天然**比 HL 的净结果好一截，这不是策略更强。
3. **盘口深度约 1/5**。回测按「开盘价 + 0 滑点」成交，在 Lighter 上比在 HL 上更乐观；
   第 5 节给了 5bps 的敏感性（CAGR 从 +25.7% 掉到 +18.5%）。
4. **资金费方向不同**。Lighter 这段历史里空头**收**资金费（BTC 合计 −2.2 USDC），
   HL 同一时期的资金费结构不能假设相同。
5. **成交假设不同**。本引擎明确写了「同 bar 止损优先」「入场当根不判离场」「跳空按开盘价」
   （第 1 节）；旧 pandas 引擎的具体假设本次无法逐条核对（脚本不在本仓库内），
   所以**不能宣称两者绩效可比**。

**结论：** 旧基线只能证明「策略在 HL 上有效」，不能证明「在 Lighter 上同样有效」。
本文件报告的是后者，且**不把 700 笔的统计显著性借给 208 笔**。

### 6.3 关于 README/PLAN 里的「299 笔」

README 的「证据基础」表与 `docs/PLAN.md` §6 写「Lighter 过密集门槛 299 笔」。
`docs/STRATEGY_PORT.md` §4 已经注明：那个数字与冻结口径的 1,251 笔**口径不同，不要混用**。
T11 用冻结口径实跑后可以给出确定答案：

* **299 不是交易笔数**，也不该再被当作 Lighter 的证据规模引用。
* 冻结口径下的真实漏斗是第 3 节：6,874 根破线 → 1,582 根过密集 → **1,251 笔信号** →
  **208 笔成交**（含每标的至多一仓）。README 表里的「突破信号」列（1,278 / 1,241 / 1,392）
  同样是另一套统计的产物，与 `app.strategy` 的破线计数（2,344 / 2,263 / 2,267）对不上。
* 因此 **`docs/BACKTEST.md`（本文件）+ `scripts/backtest.py` 的实跑输出才是 Lighter 的
  回测证据**；README 那张表保留为「早期估算」，并已在其下方加了指向本文件的更正说明。

    → ✅ 两个引擎的统计逐项一致
  band/sma200 最大绝对差 = 0.000e+00；密集标记差异根数 = 0
…（ETH / SOL 同）

```

两层验证：

1. **信号层**：1,251 笔逐笔一致（BTC 381 / ETH 415 / SOL 455），入场价与止损价最大差
   都是 **0**。密集标记差异根数：BTC 0 / ETH 0 / SOL **1**（唯一一处是
   `scripts/backtest_engine.py` 文档里写明的 `raw[:win]=False` off-by-one 边界根，
   不影响任何信号 —— 差异根上并没有产生信号，否则信号集合会不一致）。
2. **统计层**：两侧信号各走一遍**同一个** `scripts/backtest.simulate` + `summarise`
   （`xvalidate.py` 里没有第二份统计实现），笔数/胜率/均R/CAGR/终值/最大回撤**逐项相等**。
   若两个引擎对同一段行情的交易解释不同，这一层会直接报 ❌ 并以退出码 1 失败。

## 9. 已知局限 / 诚实声明

1. **回测不代表未来。** 1.77 年、208 笔是一个小样本：BTC 单独跑只有 63 笔、CAGR +2.3%，
   组合的全部收益来自 ETH/SOL 这两段行情。**样本量不足以支撑「策略稳健」的结论。**
2. **Lighter 历史短（1.77 年 vs HL 6.10 年）、深度约 1/5。** 0 滑点的成交假设在薄盘口上
   偏乐观；5bps 就把 CAGR 从 +25.7% 打到 +18.5%。
3. **资金费按历史真实费率计提**，但未来费率结构可能完全不同（这段历史以多头付钱为主）。
4. **未建模**：强平、部分成交、下单失败重试、交易所停机、限频、资金划转延迟、
   手续费阶梯、`app.sizing` 的整数化与最小下单量（回测用连续定仓）。
   这些在实盘都会让结果变差，不会变好。
5. **单一策略、单一周期**：没有对参数做任何优化（`app/strategy.py` 冻结），
   也没有做 walk-forward / 多市场检验。这里报告的是**一处历史的实测**，不是最优参数。
6. **`--json` 里的 `trades_detail`** 只在 `--trades N` 时输出，避免 JSON 被 20 万行明细淹没。
7. **没有做的事**：不合并 HL 与 Lighter 的数字、不用 Lighter 的结果反推 HL 的结论、
   不为「让数字好看」调整任何假设或过滤条件。
